## What we built and why

REDLINE is a static web dashboard for reviewing NASA combustion investigations and the conditions behind material evidence. The problem is evidence transfer: a material name alone does not establish whether an experiment answers a question about a different specimen, atmosphere, flow or gravity. NASA's [Combustion Science page](https://www.nasa.gov/glenn/glenn-expertise-space-exploration/physical-sciences-program/combustion-science/) explains the ISS role in studying combustion and spacecraft fire risk (Overview). REDLINE organizes that research for readers considering spacecraft, stations, lunar/Mars habitats and pressurized rovers. Rockets and propellants are outside our scope.

The repository contains a source-linked investigation catalog, an investigation summary/ranking/comparison interface, a cabin form and results-table components, an oxygen slider with dated atmosphere/pre-breathe context, a research-gated gravity display, experiment/swap exploration modules, an accuracy-report viewer and an Ask REDLINE module. It uses plain HTML, CSS and JavaScript ES modules, static JSON/CSV and Node's built-in test runner, with no framework, bundler or backend.

**Delivery limits matter:** `index.html` mounts the investigation dashboard and the cabin shell. `src/main.js` still lacks form-to-result update wiring; `compare.js`, `label.js` and the evidence panel remain scaffold stubs. Gravity, accuracy and Ask REDLINE modules exist but are not connected in that entry page. The catalog's flat fields/provenance also differ from the dashboard's expected field wrappers, so complete production-catalog rendering and source links are not established by the fixture-based dashboard tests. We do not present these components as a finished cabin assessment workflow.

## NASA data and resources: what each contributes

The **[PSI Data Repository](https://psi.nasa.gov/physci/repo/) is our primary NASA dataset**. REDLINE uses its investigation metadata for discovery and comparison, rather than treating catalog descriptions as material burn thresholds. The dated [source register](../research/investigations-sources.md) records accession versions, metadata endpoints, field locators and conflicts; the [catalog](../data/investigations.json) retains per-field provenance. There are 26 catalog entries, including an ACME umbrella, shared DAFT accession and derived studies; this is not 26 independent experimental datasets.

## AI use and checking

Our detailed disclosure is [docs/ai-use.md](ai-use.md). Claude Code and Codex agents worked through GitHub issues on research, specifications, code and review. The engine assignment was described as the **Fable engine** in the build specification; in this checkout its comparison/label functions remain stubs. That assignment does not establish that a particular model completed or validated the engine. Labels are designed to come from explicit comparison rules, not language-model judgments.

Four stored AI interpretations cover the current draft evidence groups. Their recorded generator is Claude Opus 5.5, as disclosed in ai-use.md; this is repository-reported model metadata. They retain citation IDs and team-review flags. No completed coverage of all catalog investigations is claimed. Keyword/field retrieval is deterministic, not AI. The optional live-answer module sends the question and retrieved source rows to Anthropic only with a user-supplied key; the module keeps the key in page memory, marks answers as AI-generated and flags missing/unknown citations. It is not connected to the entry page. Citation checks cannot prove the answer interprets a row correctly.

Research extraction and a separate source-rechecking agent are documented in the [V1 verification report](../research/verification-report.md). Its 15/15 BASS-II rows were acceptable **as attributed draft run transcriptions**, with missing condition/result fields; that is not a label-accuracy result or proof of completed human checking. All 29 shipped evidence rows remain `draft`, with zero `verified`. We cannot claim a completed set of hand-checked, human-approved quantitative evidence rows. Human source review is still required before promotion; AI agreement and passing code tests do not replace it. AI did not conduct the NASA experiments.

## Accuracy and limitations

**Held-out accuracy: not run; no percentage available.** `research/validation-results.csv` is absent from this checkout and from the fetched accuracy-task branch. The [accuracy handoff](handoffs/issue-56.md) explicitly leaves it uncommitted pending real query data and the engine. Synthetic fixture runs test evaluation plumbing only. They do not establish performance on NASA evidence, and the 15/15 transcription audit is not a substitute.

The implemented evaluation script is designed to compare the rules with a name-only baseline using grouped leave-one-source-out splits, leakage checks and conservative reporting gates. A genuine result requires reviewed evidence, labeled holdout queries and a completed engine. Until then, no accuracy, superiority or predictive-validity claim is justified.

Missing coverage reads **“not found in the sources reviewed.”** A future evidence label must describe **“burned in testing at these conditions”** or **“close to a measured limit”**, preserve specimen/endpoint differences and link its NASA source. An oxygen-change or swap exploration is a research comparison, not an operational recommendation.

Lunar displays use an explicitly labeled estimate/assumed envelope between selected 0 g and 1 g results, not a measured lunar threshold or a universal physical bound. Short-duration simulated partial-gravity research is shown separately and remains review-gated; it must not be erased by that envelope. No on-Moon material behavior is established here. Incomplete raw-data coverage, draft extractions, source conflicts, unfinished integration and incomplete insight coverage limit the current prototype. REDLINE is evidence review, not cabin certification or NASA endorsement.
